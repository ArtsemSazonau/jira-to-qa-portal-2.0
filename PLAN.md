# QA Portal ⇄ Jira Sync — Desktop App (v2.0)

План перехода от консольного Playwright-скрипта к кроссплатформенному десктоп-приложению с UI,
треем и планировщиком: синк Jira → QA Portal, ввод рабочего времени, кнопка-сборка в CI, окно для
кредов, а позже — отчёты через локальную LLM.

Статусы в этом документе: **готово** — сделано; **MVP** — входит в первую версию; **черновик** —
направление согласовано, детали открыты; **позже** — после MVP.

## 1. Цели

Цели продукта, в порядке приоритета:

1. **Синк Jira → QA Portal** (MVP) — то, что делает скрипт v1.0, но из приложения, по расписанию и
   без `.env`.
2. **Ввод рабочего времени во внутренний тайм-трекер + просмотр в календаре** (черновик) — часы по
   шаблону, календарь для исключений, проверка перед отправкой.
3. **Удобная сборка через GitHub Actions** (MVP) — бандл приложения собирается в CI, а не только
   локально.
4. **Окно для токенов, API-ключей, логинов и паролей** (MVP) — ввод и хранение кредов через UI +
   системный keychain вместо ручной правки `.env`.
5. **Отчёты по тикетам Jira через локальную LLM** (позже) — "сделано / в работе / планируется" за
   период, Ollama, с заделом на облачных провайдеров.

Сквозные цели — относятся к каждой фиче:

- **Автотесты на каждую фичу:** unit-тесты всегда, плюс автоматический e2e, если у фичи есть UI или
  межпроцессное поведение. Подробно — §6.
- **Ресурсы:** минимальная нагрузка на систему в фоне (idle) — допустимы всплески CPU/RAM только во время
  синка, отправки времени или генерации отчёта.
- **Платформы:** macOS — первая и основная; затем Windows; Linux — low priority.

| Core / shell | **Tauri 2 (Rust)** | жизненный цикл приложения, трей, планировщик, IPC с UI | готово (lifecycle + трей) |
| UI | Vite + **React** + TypeScript | настройки, креды, расписание, статус синка, календарь времени, отчёты | готово (панель настроек) |
| Автозапуск | `tauri-plugin-autostart` (`MacosLauncher::LaunchAgent`) | старт при логине пользователя вместо демона/сервиса ОС | готово |
| Один экземпляр, уведомления | `tauri-plugin-single-instance`, `tauri-plugin-notification` | повторный запуск фокусирует окно; разовые уведомления | готово |
| Конфиг приложения (не секреты) | serde-структура → JSON (`config.rs`) | расписание, платформенные маппинги, выбранный LLM-провайдер | готово (флаги жизненного цикла) |
| Логи | `log` + `tauri-plugin-log` | сейчас только в debug-сборке, в stdout; логи релиза и окно просмотра — в §4 | частично |
| Хранилище кредов | `keyring-rs` → системный keychain (Keychain / Credential Manager / Secret Service) | Jira API token, QA Portal login/password, логин тайм-трекера, LLM API key | MVP |
| Jira REST API | **`reqwest` в Rust-ядре** | тикеты, фильтры, JQL; группировка по платформам и приоритетам — чистые функции в Rust | MVP |
| Автоматизация браузера (QA Portal) | **Node.js + Playwright (TS)**, упакован как Tauri sidecar | QA Portal считает свои параметры во фронтенде, API нет — поэтому только браузер; sidecar получает уже сгруппированные счётчики и живёт только на время синка | MVP |
| Планировщик | `tokio-cron-scheduler` (Rust) | конфигурируемые cron-задачи, минимальный оверхед в простое | MVP |
| Клиент тайм-трекера | API (`reqwest`) **или** Playwright через тот же sidecar — не решено (§5) | отправка часов, чтение уже введённого | черновик |
| CI | **GitHub Actions** + `tauri-action` | тесты на каждый push, сборка бандла | MVP |
| Тесты | сейчас: `cargo test`, `clippy`, vitest + Testing Library + jsdom, `oxlint`; далее: `wiremock`, Playwright, WebdriverIO (§6) | см. §6 | частично |
| LLM (локально) | **Ollama** (`localhost:11434` REST API) | генерация отчёта; сама модель не бандлится в приложение | позже |
| LLM (облако) | Anthropic/OpenAI HTTP API за тем же интерфейсом `LLMProvider` | включается без переделки ядра | позже |
| Сборка/дистрибуция | `tauri-cli` (`tauri build`) | `.dmg`/`.app` (mac), `.exe`/NSIS (win), AppImage/deb (linux, low priority) | готово (mac) |

### Архитектурный принцип
Тяжёлые операции (браузерная автоматизация, инференс LLM) выносятся из вечно работающего ядра во
внешние процессы, которые живут только на время задачи:
- **Sidecar Node/Playwright** — только во время шага "залогиниться и обновить QA Portal" (и, если
  тайм-трекер окажется без API, — шага отправки времени).
- **Ollama** — отдельный, самостоятельно управляемый пользователем процесс; приложение только шлёт
  HTTP-запросы.

Ядро Tauri в простое — только трей + спящий планировщик, без Chromium и без Node. Всё, что не
требует браузера (Jira REST, группировка, расписание), живёт в Rust и покрывается unit-тестами.

### Техдолг и гигиена кода (найдено на ревью)
Каждый пункт — отдельное изменение со своими тестами.
- [ ] Уничтожать окно фронтенда при закрытии вместо скрытия. Сейчас вебвью удерживается: три
      хелпера WebKit держат 45 MB против 28 MB у Rust-ядра — 62% расхода в покое ради окна,
      которое открывают раз в день. **Предусловие:** измерить, отпускает ли WebKit процессы
      после `window.close()` — он кэширует их для быстрой повторной загрузки, и если не
      отпускает, выигрыша не будет. Краевые случаи и объём правок:
      [02-hide-to-tray.md](documentation/docs/features/02-hide-to-tray.md)
- [ ] Логи в релизной сборке: сейчас `tauri-plugin-log` регистрируется только под
      `debug_assertions`, и у релиза нет ни одного лога
- [ ] Убрать дублирование `apply()`: `lib.rs` и `ipc_commands.rs` держат по одинаковой
      cfg-обёртке над `lifecycle::macos::apply`
- [ ] `Trigger::HideRequested` вместо `if` в `ipc_commands::hide_main_window` — решение должно жить в
      `policy.rs` и иметь тест
- [ ] Пересмотреть `AppConfig: Copy`, когда в конфиге появятся строковые поля (расписание, маппинги)
- [ ] `bundle.targets` вместо `"all"` и удаление секции `android` из `tauri.conf.json`

## 5. Открытые вопросы для дальнейшего планирования

- **Способ интеграции с тайм-трекером: API или Playwright.** Сначала посмотреть сетевые запросы его
  фронтенда — если там внятный JSON API, браузер не нужен. *Блокирует:* цель 2 целиком и выбор
  модуля `timesheet/client.rs`.
- **Локальное хранилище черновиков времени** — скорее всего SQLite (`tauri-plugin-sql` или
  `rusqlite`); JSON-конфиг для этого не подходит. *Блокирует:* поток черновик → проверка → отправка
  в цели 2. Тот же выбор решит формат истории синков/отчётов.
- **Упаковка sidecar.** Node-рантайм + Chromium — порядка 200 MB. Варианты: бандлить всё; использовать
  установленный у пользователя Chrome (`channel: 'chrome'`); скачивать браузер при первом запуске.
  *Блокирует:* sidecar-синк цели 1 и размер бандла в цели 3.
- **Подпись кода / Apple Developer ID.** Без подписи Gatekeeper блокирует скачанный `.app`, а
  keychain заново спрашивает доступ после каждой пересборки, потому что меняется подпись бинарника.
  *Блокирует:* распространение сборок из CI (цель 3) и удобство окна кредов (цель 4).
- **Стоимость macOS-минут в GitHub Actions**, если репозиторий приватный — они тарифицируются с
  множителем. *Блокирует:* частоту CI-прогонов в цели 3 (каждый push или только PR/тег).
- **Нужно ли шифровать несекретный конфиг** (расписание, маппинги) или он может храниться как есть.
  *Блокирует:* ничего в MVP; решить до появления в конфиге чего-то чувствительного.

## 6. Стратегия тестирования

**Правило.** Каждая фича поставляется с unit-тестами, плюс автоматический e2e, если у неё есть UI
или межпроцессное поведение. Ручной чек-лист
([functional-checklist.md](documentation/tests/functional-checklist.md)) — только для того, что
требует глаз, строки меню или перезагрузки.

**Живые системы** (Jira, QA Portal, тайм-трекер) трогаются только вручную и только через режим
dry-run: приложение считает и показывает, что изменило бы, но ничего не пишет. **CI никогда не
пишет в реальные системы** и не держит их кредов.

| Слой | Чем | Что покрывает |
|---|---|---|
| Чистая логика Rust | `cargo test` (inline `#[cfg(test)]` + `tests/`) | политика жизненного цикла, конфиг, группировка Jira, шаблон часов |
| HTTP-клиенты (Jira, тайм-трекер, Ollama) | `cargo test` + мок-сервер `wiremock` | auth, пагинация, ошибки, разбор ответов |
| Page objects sidecar | Playwright против локальной HTML-фикстуры портала | селекторы и шаги без доступа к настоящему QA Portal |
| UI-компоненты | vitest + Testing Library + jsdom, `lib/ipc.ts` замокан | ветки рендера, ошибки, доступность |
| UI-потоки | Playwright против `vite dev` + `mockIPC` из `@tauri-apps/api/mocks` | многошаговые сценарии без Tauri и бандла |
| E2E приложения | WebdriverIO + драйвер с поддержкой macOS — **оценить:** `tauri-plugin-wdio-webdriver` или `@crabnebula/tauri-driver` | окно, IPC, жизненный цикл в собранном приложении |
| Ручной чек-лист | [functional-checklist.md](documentation/tests/functional-checklist.md) | строка меню, Dock, тёмная тема, VoiceOver, перезагрузка |
| Производительность | [performance.md](documentation/tests/performance.md), локально | дельта к idle-базе после каждой тяжёлой фичи |

Всё, кроме ручного чек-листа и производительности, запускается в CI (цель 3).
